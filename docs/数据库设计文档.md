# Skyeye 数据库设计文档

## 1. 设计理念

### 1.1 DynamoDB 单表设计 (Single Table Design)

系统使用 **一张 DynamoDB 表** 存储所有业务实体（用户、项目、合同、报销、验收、库存等），通过 **PK（分区键）+ SK（排序键）** 的组合来区分不同实体。

**为什么选择单表设计？**
- 减少表数量，简化运维
- 降低成本（单表按需付费）
- 支持事务操作跨实体
- 20人小规模系统，数据量有限，Scan操作性能可接受

### 1.2 表配置

| 配置项 | 值 |
|--------|------|
| 表名 | `skyeye-dev` |
| 分区键 (PK) | String |
| 排序键 (SK) | String |
| 计费模式 | PAY_PER_REQUEST (按需) |
| 时间点恢复 | 已启用 |
| 加密 | AWS 托管密钥 |

### 1.3 全局二级索引 (GSI)

| 索引 | 分区键 | 排序键 | 投影 | 用途 |
|------|--------|--------|------|------|
| GSI1 | GSI1PK (String) | GSI1SK (String) | ALL | 按类型/状态查询 |
| GSI2 | GSI2PK (String) | GSI2SK (String) | ALL | 按项目关联查询 |

| **GSI1PK** | `INVOICE_CONTRACT#{contract_id}` | `INVOICE_CONTRACT#2c450532` |
| **GSI1SK** | `INVOICE#{issue_date}#{invoice_id}` | `INVOICE#2026-03-01#e5f6a7b8` |
| **GSI2PK** | `PROJECT#{project_id}` | `PROJECT#939b711f` |
| **GSI2SK** | `INVOICE#{invoice_id}` | `INVOICE#e5f6a7b8` |

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| invoice_id | String | ✅ | 发票ID |
| batch_id | String | ✅ | 所属批次 |
| invoice_no / invoice_code | String | | 发票号码 / 发票代码 |
| category | String | ✅ | material(材料)/construction(施工)/service(技术服务)/other |
| tax_rate | Number | ✅ | 税率，**小数存储**（13% → 0.13） |
| amount_with_tax | Number | ✅ | 含税金额 |
| amount_without_tax | Number | | 不含税金额（默认按税率换算，可手工覆盖） |
| tax_amount | Number | | 税额（默认按税率换算，可手工覆盖） |
| issue_date | String | | 开票日期（默认继承批次） |
| buyer_name / seller_name | String | | 购买方 / 销售方 |
| contract_id / contract_no / project_id / project_name | String | | 继承批次 |
| remarks | String | | 备注 |
| attachments | List[AttachmentMap] | | 发票扫描件/PDF |
| entity_type | String | ✅ | 固定值: `invoice_record` |

**注意：** 批次与其发票共用 PK（`INVOICE_BATCH#{batch_id}`），通过 SK 区分：`META` 是批次本身，
`INVOICE#{invoice_id}` 是该批次的发票 —— 一次 Query 取出整批，与 Material/StockRecord 同一套做法。
手工覆盖不含税/税额时校验 `|不含税 + 税额 − 含税| ≤ 0.02`，超出直接拒绝。

## 4. S3 存储设计

### 4.1 Bucket 结构

```
skyeye-attachments-{account_id}/
├── contract/{contract_id}/
│   ├── {file_id}.pdf          # 合同PDF
│   ├── {file_id}.jpg          # 发票图片
│   └── {file_id}.png          # 到款截图
├── project/{project_id}/
│   ├── {file_id}.xlsx         # 预算表
│   └── {file_id}.pdf          # 报价单
├── invoice/{batch_id}/
│   └── {file_id}.pdf          # 发票扫描件（按批次归档）
├── reimbursement/{reimburse_id}/
│   ├── {file_id}.pdf          # 发票 / 会计凭证
│   └── {file_id}.jpg          # 收据
├── acceptance/{acceptance_id}/
│   ├── {file_id}.pdf          # 验收报告
│   ├── {file_id}.dwg          # CAD图纸
│   └── {file_id}.docx         # Word文档
└── inventory/{record_id}/
    └── {file_id}.pdf          # 入库凭证
```

### 4.2 上传流程

```
前端 → POST /api/upload/presigned-url (获取预签名URL)
     ← { upload_url, file_id, s3_key }
前端 → PUT upload_url (直接上传到S3)
前端 → 将 {file_id, s3_key, file_name, ...} 保存到实体的attachments字段
```

### 4.3 下载流程

```
前端 → GET /api/upload/presigned-download?s3_key=xxx
     ← { download_url }
前端 → 打开 download_url (直接从S3下载)
```
