# Skyeye 系统架构设计文档

## 1. 系统概述

Skyeye 是一套面向20人规模弱电工程公司的内部信息管理系统，采用 AWS Serverless 架构，实现合同管理、报销审批、验收归档、项目分析和库存管理的全流程数字化。

## 3. 技术选型

| 层级 | 技术 | 选型理由 |
|------|------|---------|
| **前端** | React 18 + TypeScript | 类型安全，组件化开发，生态丰富 |
| **UI框架** | Ant Design 5 | 企业级 UI 组件库，中文友好，表格/表单功能强大 |
| **构建工具** | Vite 5 | 极速热更新，构建速度快 |
| **图表** | Recharts | React 原生图表库，轻量级 |
| **后端** | FastAPI (Python 3.12) | 高性能异步框架，自动 Swagger 文档，类型安全 |
| **ORM** | PynamoDB 6 | DynamoDB 的 Pythonic ORM，支持单表设计 |
| **Lambda适配** | Mangum | 将 FastAPI ASGI 应用适配为 Lambda handler |
| **数据库** | DynamoDB | Serverless，按需付费，毫秒级延迟，自动扩展 |
| **对象存储** | S3 | 附件存储，支持 Presigned URL 直传 |
| **CDN** | CloudFront | 全球加速，HTTPS，SPA 路由支持 |
| **API网关** | API Gateway | 限流、CORS、与 Lambda 集成 |
| **IaC** | AWS CDK (TypeScript) | 基础设施即代码，类型安全，AWS 官方推荐 |
| **认证** | JWT | 无状态认证，适合 Serverless 架构 |

## 5. 分层架构

系统采用经典三层架构：

```
┌───────────────────────────────────────┐
│          Presentation Layer           │
│    React + Ant Design + Recharts      │
│    (SPA, 路由守卫, JWT Token管理)      │
├───────────────────────────────────────┤
│          Business Logic Layer         │
│    FastAPI Routers + Schemas          │
│    (输入验证, 权限控制, 业务流程)        │
├───────────────────────────────────────┤
│          Data Access Layer            │
│    PynamoDB Models (Single Table)     │
│    (DynamoDB CRUD, S3 Presigned URL)  │
└───────────────────────────────────────┘
```

### 5.1 前端层
- **路由守卫**: 未登录用户自动重定向到 `/login`
- **JWT管理**: Token 存储在 localStorage，Axios 拦截器自动附加
- **401处理**: Token 过期自动清除并跳转登录页
- **角色菜单**: 根据用户角色动态显示菜单项

### 5.2 业务逻辑层
- **FastAPI Router**: 每个模块独立路由文件
- **Pydantic Schema**: 请求参数自动验证和序列化
- **依赖注入**: `get_current_user` 和 `require_roles` 实现认证和授权
- **统一响应**: `APIResponse` 标准化所有 API 返回格式

### 5.3 数据访问层
- **单表设计**: 所有实体共用一张 DynamoDB 表
- **PK/SK模式**: 通过复合键实现不同实体的存储和查询
- **GSI**: 两个全局二级索引支持多维度查询
- **Scan过滤**: 20人小规模系统使用 Scan+内存过滤（性能足够）

## 6. 认证与授权

### 6.1 认证流程

```
用户登录 → POST /api/auth/login
    → 验证用户名密码
    → 检查账号锁定状态
    → 生成 JWT Token (24h有效期)
    → 返回 Token + 用户信息

请求API → Authorization: Bearer <token>
    → Axios 拦截器自动附加
    → FastAPI Depends(get_current_user) 解析
    → 验证Token有效性和过期时间
```

### 6.2 权限模型

```python
require_roles("admin")                    # 仅管理员
require_roles("admin", "finance")         # 管理员或财务
require_roles("admin", "project_manager") # 管理员或项目负责人
get_current_user                          # 任何已登录用户
```

### 6.3 安全机制
- **密码加密**: SHA-256 + Salt 哈希存储
- **登录锁定**: 连续3次失败锁定1小时
- **JWT过期**: Token 24小时自动过期
- **CORS**: 开发时允许所有来源，生产可配置

## 7. 部署架构

```
开发者本机
    │
    │ ./deploy.sh my-profile us-east-1
    │
    ├─→ CDK Bootstrap (首次)
    ├─→ CDK Deploy SkyeyeBackend
    │     → DynamoDB Table (skyeye-dev, PAY_PER_REQUEST)
    │     → S3 Bucket (skyeye-attachments-{account})
    │     → Lambda Function (skyeye-api, Python 3.12, 512MB)
    │     → API Gateway (skyeye-api, /api stage)
    │
    ├─→ npm run build (前端构建, 注入API_URL)
    │
    └─→ CDK Deploy SkyeyeFrontend
          → S3 Bucket (skyeye-frontend-{account})
          → CloudFront Distribution (HTTPS, SPA路由)
          → S3 BucketDeployment (上传前端构建产物)
```

## 8. 性能考量

| 指标 | 设计值 | 实现方式 |
|------|--------|---------|
| 页面加载 | < 3s | CloudFront CDN + Vite 构建优化 |
| API响应 | < 1s | Lambda 512MB + DynamoDB PAY_PER_REQUEST |
| 并发能力 | 20人 | Lambda 自动扩展 + DynamoDB 按需 |
| 附件上传 | < 10s (50MB) | S3 Presigned URL 直传，不经过 Lambda |
| 数据存储 | 10万+ 记录 | DynamoDB 无容量上限 |
| 附件存储 | 100GB+ | S3 无容量上限 |
